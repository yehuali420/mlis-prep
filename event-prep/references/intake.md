# 输入读取与事实卡

## 事实卡：10个字段
| 字段 | 记录要求 | 缺失后果 |
|---|---|---|
| 活动全称 | 按原文记录，不擅自缩写 | 无法统一文件名、对外口径 |
| 主办方 | 机构/部门/联系人原称 | 无法确认决策与审批链 |
| 我方角色 | 主办、承办、协办、参展、参赛或参与者 | 易越权承诺或漏掉义务 |
| 日期与每日时段 | 日期、报到、布展、正式开始、结束、撤场分别记 | 倒排和到场时间失真 |
| 地点 | 校区/楼宇/楼层/房间或摊位号/集合点 | 人员和物资可能到错地点 |
| 硬性要求 | 原话摘录，含禁限事项、格式、数量、考核 | 可能违反规则或漏交 |
| 交付物 | 名称、规格、份数、对象、提交方式 | 无法验收 |
| 联系人 | 姓名/角色/联系方式/可联系时段；无则未明确 | 出事无升级对象 |
| 预算与来源 | 上限、可用余额、审批人、垫付与报销规则 | 可能超支或无法报销 |
| 参会人群 | 人数范围、身份、报名/邀请方式、特殊需求 | 物资与容量估算失准 |

## 不同输入的解析要点
- **DOCX**：读取正文、表格、页眉页脚、批注及附件清单；区分正式要求和修订痕迹，记录版本日期。
- **PDF**：检查所有页面、表格、脚注和附录；扫描件需OCR，低置信文字标待核，不凭猜测补齐。
- **邮件/群通知**：保留发送者、时间戳、引用回复、@对象、附件和后续更正；按时间顺序合并，冲突不覆盖，单列差异。
- **截图**：检查裁切边缘、图片文字、群名、发送时间和上下文；模糊数字/日期标未确认，不按视觉猜数。
- **口头转述**：分开记录“原话转述”“转述者理解”“待核事实”；尽可能要求原通知或联系人确认。
- **链接**：记录页面标题、访问日期、版本/更新时间、附件及权限限制；无法访问时明确写出，不能假装已读取。

## 必问清单：三条判定标准
只有答案会改变物理交付、关键排期或权限边界时才提问：
1. **规格问题**：尺寸、格式、数量、分辨率等变化会导致返工、无法安装或无法提交。默认值例：海报A3、PNG/PDF双格式、数量1份电子版。
2. **真实截止问题**：不同日期会改变关键路径、缓冲或是否来得及。默认值例：按通知中最早出现且可执行的截止时间准备，并标注待确认。
3. **权限边界问题**：桌位、电源、入场人数、场地使用、费用承担等决定活动能否开展。默认值例：不假设可用电、不假设可现场付款，先按无电源和预算需审批规划。

### 反面例子（不要问）
- “希望活动氛围是什么风格？”——通常可先用稳妥、中性方案假设。
- “想不想做推文？”——可依据通知交付要求决定；未要求则列可选项。
- “要不要多买一些小礼品？”——属于可选采购，按预算分档处理。
- “负责人喜欢什么颜色？”——不影响关键交付或权限，先按组织视觉规范假设。

## 假设清单写法
每条必须写：**假设｜依据｜不成立时的影响/切换动作**。
- 假设：现场可在正式开始前45分钟进入；依据：常规校园活动布置惯例，通知未说明；影响：若不成立，改为提前一天预布置并压缩非必要装饰。
- 假设：报名人数暂按30–50人估算；依据：没有报名数据；影响：若超过50人，增加签到岗并启用备用座位。
假设不得伪装成通知事实；优先采用低成本、可逆、偏保守的默认值。

## 四项矛盾检测
- **时间矛盾**：截止日早于通知发送日、活动日早于准备动作、时间段重叠或“下周”指代不明。动作：列出原文与日历日期，按最早可信期限做最坏情况方案。
- **地点矛盾**：不同材料给出不同楼宇/房间/摊位，或集合点与活动点混淆。动作：分别引用来源，未确认前按更严格的进场/运输要求准备，不擅自选一个当事实。
- **责任矛盾**：主办方与我方对同一交付物的责任人不同，或任务无人认领。动作：指定我方临时跟进人而非替对方承诺，设置确认死线及升级联系人。
- **口径矛盾**：名称、人数、费用、宣传承诺、报名方式、活动版本不一致。动作：保留各版本和来源，暂停发布不可逆信息，准备保守版内容并请有权限者拍板。
