# 输入解析、来源登记与防幻觉闸门

## 1. 事实卡
每项事实都必须有来源编号；原文未提供的字段留空并转入“未锁定事项表”，不得猜测。

| 字段 | 记录方式 | 来源/定位 | 状态 |
|---|---|---|---|
| 活动全称 | 原文照录，不擅自缩写 | S1，文件名/页码/段落或消息时间 | 已证实/需核实 |
| 主办/协办机构 | 原称照录；合作关系须有明确依据 | 来源编号 | 已证实/需核实 |
| 我方角色 | 仅按通知明确角色填写 | 来源编号 | 已证实/需核实 |
| 日期与时段 | 分开记报到、布展、正式开始、结束、撤场 | 来源编号 | 已证实/需核实 |
| 地点/摊位 | 校区、楼宇、楼层、摊位号分别记录 | 来源编号 | 已证实/需核实 |
| 硬性要求 | 关键句逐字引用，保留限制条件 | 来源编号 | 已证实/需核实 |
| 交付物与规格 | 名称、格式、尺寸、数量、提交方式 | 来源编号 | 已证实/需核实 |
| 联系人/权限 | 仅记录来源中出现的姓名、角色、联系方式 | 来源编号 | 已证实/需核实 |
| 预算 | 上限、资金来源、审批人、垫付/报销规则 | 来源编号或报价单 | 已证实/估算/未知 |
| 受众与人数 | 区分已报名数、预计数、未经证实的估计 | 来源编号 | 已证实/估算/未知 |

## 2. 来源分级
- **S（源文件事实）**：用户上传的通知、会议手册、邮件、官方文件；记录文件名、版本、页码/段落或消息时间。
- **V（外部核验）**：官方网站、官方公告、正式主办方回复；记录标题、链接、访问日期和相关段落。
- **I（推断/建议）**：模型根据任务提出的方案、估算、通用经验。必须标“建议/估算”，不能伪装成主办方要求或已发生事实。
- **U（未知）**：没有证据。写“未提供/需核实”，不要补造。

机构、合作关系、科研成果、观测数据、姓名/职务、日期、场地规则、联系方式、预算报价都属于高风险事实。没有 S 或 V 级证据时，不得作为事实陈述。领域知识可以解释术语，但不能证明某机构确实参与了本次活动。

## 3. 文件读取规则
- DOCX：检查正文、表格、页眉页脚、批注、附件清单和版本号；区分修订痕迹与正式文本。
- PDF：检查全部页面、表格、脚注、附录；扫描件 OCR 低置信内容标需核实。
- 邮件/群通知：保留发送者、时间戳、引用回复、附件和后续更正；按时间排列，冲突并列记录。
- 截图：模糊数字、裁切内容和缺少上下文的文字不得猜测。
- 链接：记录标题、访问日期、版本；无法访问就明确说明，不能假装读过。
- 用户转述：分开写“转述内容”和“已核实事实”；优先索取原始通知或正式回复。

## 4. 未锁定事项表（强制）
所有未确定事项逐条占一行，统一使用此表，不在正文重复叙述。

| 事项 | 当前状态 | 负责人（留空） | 需在何时前确认 | 确认后动作 |
|---|---|---|---|---|
| 例：易拉宝尺寸 | 通知称规格稍后公布；当前未知 |  | 需立即向主办方确认；具体时间未提供 | 按正式规格调整版面并复核文件 |
| 例：摊位开放时段 | 未提供 |  | 确认排班前 | 锁定到场、轮岗和撤场时间 |

要求：
- 负责人未知就留空，不写虚构姓名，也不默认某人兼任。
- 截止时间未知时写“需立即确认（主办方未给出时间）”；不得自行发明截止日期。
- 若必须给内部目标日期，标注“内部建议期限”，并写清这是建议而非主办方死线。
- 人员不确定统一进入岗位分工表，岗位存在但无人认领时主责和替补单元格留空。
- 相对日期如“下周二”必须写出原文、基准日期、换算结果与歧义；不明确基准或与活动时间冲突时保持未锁定。

## 5. 必问规则
最多优先提出三类会改变物理交付或关键路径的问题：
1. 规格：尺寸、文件格式、数量、分辨率、打印方式。
2. 截止：提交的具体日期、时刻、时区、接收方式。
3. 权限：摊位、用电、入场、搭建、摄影/录音、费用承担。
问题必须同时给出当前状态、确认责任岗位、确认期限和确认后动作。若负责人尚未指定，负责人单元格留空；可另列建议责任岗位但不得当成已指派。

## 6. 矛盾检测
| 矛盾类型 | 检测方法 | 处理规则 |
|---|---|---|
| 时间 | 截止早于通知时间、活动已开始才要求交付、相对日期歧义 | 引用原文并标风险；立即询问发布方；按最早可信期限做可逆准备 |
| 地点/权限 | 不同材料地点冲突、桌位/电源/进场权限缺失 | 不擅自选定；暂停不可逆采购和承诺 |
| 责任 | 我方/主办方责任冲突、岗位无人认领 | 进入统一表格；确认后再锁定执行 |
| 名称/数字/合作 | 机构名称、人数、经费、科研成果或合作表述不一致 | 并列来源与版本；对外发布前由有权限者核验 |

## 7. 假设管理
假设只能作为方案分支，不得混入事实区。每条假设写清：假设内容｜依据（通常为缺失信息或低风险规划选择）｜不成立时影响｜切换动作。涉及机构、科研、人物、数据、合作关系的事项不得用假设补位，应留空/需核实。
