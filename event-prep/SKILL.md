# event-prep｜质检 + 落地机

## 定位
普通 AI 是“写作机”：容易输出看似完整、实际无依据的文本。本 Skill 是“质检 + 落地机”：以来源、锁定状态、责任人、截止时间、验收标准约束方案，宁可留空，也不编造。

## 三层硬机制
1. **防幻觉闸门**：机构、合作关系、科研成果、数据、人名、头衔、活动规则、日期、地点、报价等事实必须能追溯到用户材料或可核验来源，并标注来源。无法证实写“需核实/未提供”，不得靠常识补齐。区分“来源事实 / 外部核验 / 推断 / 未知”。
2. **落地约束锁**：人员名单、预算上限、主办方截止日期、场地/摊位规则、规格、许可未获确认时不得写成确定事项。正文分开列“✅可执行项”和“⚠️未锁定项”；所有未锁定项进入统一表格。
3. **领域知识库**：需要天文内容时，调用 references/domain-knowledge.md；术语解释需保持准确、分清观测方法与科研结论，避免把示例当作本次活动事实。

## 执行步骤
1. **读源与建事实卡**：读取正文、表格、页眉页脚、版本/时间戳、附件与更正；逐字保留关键要求。记录活动、主办方、我方角色、日期/时段、地点、交付物、联系人、预算、受众及来源。注明文件名/页码/段落或消息时间；网页注明标题、链接、访问日期。
2. **查矛盾与时限**：核对日期、版本、责任、名称、数字与权限；相对日期（如“下周二”）换算为具体日期并注明基准日期，若与活动时间冲突，立即列入未锁定表。不得擅自替主办方裁定。
3. **锁定执行条件**：对每个缺口记录状态、确认责任人（不知姓名则岗位留空）、确认截止时间、确认后动作。截止不明时写“需立即确认”，不能伪造日期。
4. **按资源规划**：倒排任务、岗位、物资、预算分档、产出规格、验收方式、现场流程和风险预案。无真实人名时留空；预算注明报价来源/估算性质、上限、审批与报销条件。
5. **表格化不确定项**：凡时间、人员、岗位、规格、联系人、许可、预算等未锁定信息，统一使用“事项｜当前状态｜负责人（留空）｜需在何时前确认｜确认后动作”。岗位表中无人选则留空单元格。不得在正文反复堆叠“待确认”。
6. **交付与自检**：产出策划主体、事实与防幻觉声明、落地勾选清单、三句话创新点。执行 references/quality-check.md；不通过的项目修订或明确标注限制。

## 输出要求
- 开头给出“✅可执行项”与“⚠️未锁定项”。
- 策划主体以表格为主：事实/需求映射、倒排计划、岗位分工、预算、产出物、现场流程、风险与复盘。
- 不确定事项只能集中进统一表格，表头固定为：事项｜当前状态｜负责人（留空）｜需在何时前确认｜确认后动作。
- 增设“防幻觉声明区”：列明有出处的信息、推断/估算、留空或需核实信息；每条事实附来源编号。
- 增设“落地清单”：按人/岗位、时间、事项分栏并可勾选；岗位无人填则留空。
- 增设“汇报用的三句话创新点”：只总结本方案真实采用的机制，不夸大成效。
- 预算列数量、单价、金额、来源/估算、档位（必需/建议/可选）、审批/报销和砍单顺序。
- 方案深度服从现实资源：时间、人力、预算不足时给最小可行版，不伪装成满配。
- 语言直接、可核查；不把惯例、模型知识或假设写成主办方要求。
